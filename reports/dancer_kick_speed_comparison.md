# B-Human / 原 dancer 出球速度对照

## 结论

本次重新进行的 7v7 测试中，B-Human + 当前服务器的有效脚部出球水平初速度均值为
**3.205 m/s（22 次）**，原 dancer 当前源码 + `test/unfair_kick` 为
**5.194 m/s（15 次）**。前者比后者约低 **38.3%**。这是本次短时样本的描述统计，
不是永久固定的性能比例，也不是从最近一次历史比赛日志直接还原出的均值。

最有力的原因证据是**球接触的刚度/阻尼设置不同**：当前只把机器人和球半径/质量
临时对齐了 unfair，球接触仍采用 SimRobot T1 对齐后的 `solref=(0.02,1)`；
unfair 使用 `solref=(-5000,-20)`。保持相同网络和相同起始条件，仅恢复这个参数，
16 组单机实验平均出球速度从 2.933 增到 3.934 m/s。

网络、K1 模型、关节力矩上限和固定 command 没有发现两边不一致。
交叉比赛检查也支持物理环境的影响：B-Human 换到 unfair 为 5.265 m/s；
原 dancer 换到当前物理为 3.547 m/s。客户端战术、方向和头控仍不同，
不能把全部对局差异精确分摊给一个物理参数；当前证据也不能推导整场得分收益。

## 对照对象与运行方式

- B-Human：当前 `feature/rcssservermj-7v7` 工作区，`--motion-policy dancer --server-model K1`；
  包含已确认的 300 ms / 140 ms / 1200 ms 过渡及已移除的 native_motion_guard。
- 原 dancer：`test/7vs7`，提交 `aba39596950847771d9ab558a00afab995ff8335`，用户确认的默认 normal 等变 VisualKick。
- unfair 服务器：本地 `test/unfair_kick` 提交 `42c8f60c0053fe7cf8fc9f3fca9c60469d8b8764` 的独立归档快照。
- 当前服务器：当前 `feature/bhuman-7v7` 工作区，fifa7vs7、ssim、`--bhuman-physics`。
- 所有比赛使用同一个 Apollo 包，主队左侧先开球，双方各 7 人，sync、no-realtime，
  每次 120 秒仿真时间。独立端口，串行比赛，避免 Apollo 队内广播相互影响。
  两个主对照各重复两次；交叉对照各一次。共 6 场、12 分钟仿真时间。
- 原 dancer 现存 `build_sim/run_player` 不支持当前源码已有的 `--server-profile`，
  与当前分支不一致。因此在实验目录独立编译当前源码用于对照，未覆盖原二进制，
  未修改 dancer 源码。首次旧二进制启动失败没有进入比赛，也没有计入统计。

随机种子不控制 Apollo 和线程/TCP/UDP 调度，比赛轨迹不构成严格配对。
因此比赛结果按逐场和汇总统计报告；真正配对的因果检查使用后面的单机实验。

## 初速度统计口径

最近一次正常启动的 CSV 保存了机器人行为和 BallModel，server console 也未保存完整
球速度/触球序列，不能可靠计算该历史场次真实的出球初速度。因此本次重新采集 server 真值。

1. 使用服务器每 20 ms 的球世界速度、脚部接触和机器人姿态记录；不用视觉位置差分估速。
2. 同球员、接触间隔不超过 200 ms 的触球归并为一次；取最后触球后第一个无接触帧的球速度。
3. 主指标为水平速度 `hypot(vx,vy)`，至少 1 m/s；触球机器人根高度至少 0.35 m，倾斜不超过 45°。
4. 必须存在脚部接触；排除离脚帧同时发生其他触球、裁判模式切换或明显传送。
   没踢到球的尝试、不足门限的轻蹭球和倒地碰球不计入“有效出球”。
5. 网络帧分辨率为 20 ms，所以这是**离脚后首个采样帧速度**，不是精确分离瞬间的连续时间值；
   极短触球有可能未被网络帧接触记录捕获。不同物理步长均按同一 20 ms 口径统计。

主指标包含站立/行走期间符合上述条件的脚部出球。后面另列只保留最后触球时 Kick policy
正在运行的结果；两种口径方向一致。附列三维速度，避免把垂直分量混淆为水平减速。

## 参数核对

- K1 `robot.xml` SHA-256 完全相同：`aed717d353f53e801e86b99f5ed616672081c555dc359da49cb280de2c64e4fb`；引用的 24 个 mesh 也全部相同。
- VisualKick ONNX SHA-256 完全相同：`c9bc1be6e373145ceccd6d0bd3036b68386909ad33d272c865218b1a4c1fb68e`。
- 默认身体姿态、Kp/Kd、动作裁剪/缩放、速度缩放均一致；固定 command `(1,0,1)`，步频 1.8 Hz。
- 以新编译的原 dancer probe 做 200 帧数值对照：VisualKick 动作/观测/目标误差上限
  `1.49e-6`，AMP 200 帧误差上限 `2.62e-6`。这验证相同输入下的部署数值，
  不代表比赛时头控、目标方向和历史观测一定相同。

| 参数 | 当前比赛物理 | unfair 默认物理 |
|---|---|---|
| 球半径 / 质量 | 0.11 m / 0.41 kg | 相同 |
| 球惯量 | 0.0019844 kg·m²，各轴 | 相同 |
| 球 solref | `(0.02, 1)` | `(-5000, -20)` |
| 球摩擦：滑动 / 扭转 / 滚动 | `(0.5, 0.007, 0.007)` | `(0.4, 0.01, 0.01)` |
| 物理步长 / 网络周期 | 2 ms / 20 ms | 5 ms / 20 ms |
| 积分器 | Euler | implicitfast |
| Newton 迭代 / 线搜索 | 50 / 50 | 10 / 20 |
| tolerance | 1e-6 | 1e-8 |
| 重力 z | −9.80665 | −9.81 |
| 空气 density / viscosity | 0 / 0 | 相同 |

MuJoCo 的正值 solref 表示时间常数和阻尼比；负值表示直接指定刚度和阻尼。
`(0.02,1)` 为 20 ms 时间常数和临界阻尼；`(-5000,-20)` 使用不同的刚度及较低的阻尼，
更容易保留碰撞反弹。两者不是同一组参数的不同写法，也不是恢复系数的直接数值。
含义见 [MuJoCo 官方说明](https://mujoco.readthedocs.io/en/stable/modeling.html#solver-parameters)。

## 单机配对实验：区分物理参数原因

每个配置使用相同的 16 组种子：相同 K1、网络、初始关节扰动、球位和目标方向；
初始球距 0.8～2 m。相同 50 Hz 推理、25 Hz 无噪声球采样、确定性头控，
无裁判、对手、相机遮挡和网络调度。以第一个符合 ≥1 m/s 的脚部出球作为该次结果。
所有组的 16 次均得到有效出球，未将无出球尝试从某一组单独剔除。
首个摔倒或 10 秒终止；部分配置出球后出现摔倒，因此这里仅用于速度因果检查，
不能用来宣称换参数的稳定性收益。

| 配置 | 16 次均值 m/s | 对当前基线变化 m/s |
|---|---:|---:|
| 当前物理基线 | 2.933 | +0.000 |
| 完整 unfair 物理 | 3.555 | +0.622 |
| 仅恢复球 solref | 3.934 | +1.001 |
| 仅恢复球摩擦 | 2.967 | +0.034 |
| 恢复球/地面接触参数 | 3.966 | +1.033 |
| 仅恢复步长、积分器、求解器等数值配置 | 2.839 | -0.094 |

“数值配置”一组同时恢复 timestep、integrator、solver、iterations、ls_iterations、
tolerance、gravity、density、viscosity；它不是单独对 Euler 的判断。
“仅恢复球 solref”代码还复制 solimp，但两边的 solimp 本来就相同。

按种子配对 bootstrap（10000 次）的差值 95% 区间：完整 unfair 为 **+0.29～+0.88 m/s**，
仅恢复 solref 为 **+0.89～+1.12 m/s**。仅恢复数值配置为 **−0.34～+0.08 m/s**，
本组没有观察到与接触参数同量级的正向增幅。参数通过闭环动作产生交互，不能简单相加各组增益。

这组数据证明球接触设置能够造成明显速度差；它与比赛的起始分布不同，
不能把其绝对均值替代比赛均值，也不能拿两组均值之差计算每个因素在整场比赛中的精确贡献。
